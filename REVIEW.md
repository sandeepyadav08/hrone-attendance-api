# REVIEW.md

Defects found in the starter `app/main.py` (helpers and endpoints).

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` (module level) | Client is not `tz_aware`, so PyMongo returns naive datetimes. Comparing or subtracting them with aware values crashes, and treating them as local time shifts every instant. | Read a seeded record and compute `punch_out - punch_in` against an aware value: `TypeError: can't subtract offset-naive and offset-aware datetimes`. | `MongoClient(..., tz_aware=True, tzinfo=UTC)`. |
| 2 | module level / startup | No indexes are created. There is no unique key on `employees.emp_code` or on `attendance_logs(emp_code, date)`, and every list/analytics query is a COLLSCAN. | `explain` shows `COLLSCAN`. Duplicate employees and duplicate day records can be inserted. | `create_indexes()` runs at startup through `lifespan`. It creates two unique indexes plus indexes for each list/analytics query. `create_index` is idempotent. |
| 3 | `health` | Always returns 200, even when MongoDB is down. | Stop mongod: `/health` still says `ok`. | `ping` MongoDB. On failure return 503. |
| 4 | `compute_late_minutes` | Grace check uses whole minutes (`minutes > 10`), so 09:40:01 to 09:40:59 is treated as on time. The rule is strictly more than 10:00 (600 s). | Shift 09:30, punch 09:40:01 returns 0. Expected 10. | Compare seconds `> 600`, then `seconds // 60`. |
| 5 | `compute_late_minutes` | Builds shift start with `punch_in.replace(hour, minute)`, which keeps the punch's own date and time zone (UTC/server time, not IST). For overnight shifts, a punch after midnight is compared with the wrong day's start. | Punch 09:45 IST stored as 04:15 UTC: replace sets 09:30 UTC, giving a negative or wrong result. Overnight 22:00 shift, punch 01:00: late should be 180. | Shift start is built in IST on the attendance date from R1 (`at_ist(day, shift_start)`). |
| 6 | `compute_work_hours` | `round()` is float, round-half-even. R4 needs decimal half-up. Milliseconds are not truncated first. | 4 h 29 m 42 s = 4.495 h: `round` returns 4.49 and marks a half day. Expected 4.50, not a half day. | `Decimal(seconds)/3600` with `quantize(0.01, ROUND_HALF_UP)` on second-truncated instants. |
| 7 | `compute_overtime` | No 30-minute minimum (R3). For overnight shifts, shift end is placed on the start date instead of the next day. | Out at 18:45 for an 18:30 end returns 15. Expected 0. Night shift 22:00 to 06:00, out 06:40 next day returns about 1480 min. Expected 40. | Return minutes only if `>= 30`. `shift_end_dt` adds one day when `shift_end <= shift_start`. |
| 8 | `EmployeeIn` | No validation. Any `emp_code`, email, shift string or date is accepted. `shift_start == shift_end` is accepted. | POST `{"emp_code":"x","shift_start":"25:99","joined_on":"hello"}` returns 201. | Pydantic constraints from the contract (pattern, lengths, HH:MM, real date) and a model validator for equal shifts. |
| 9 | `create_employee` | Check-then-insert is a race. Two parallel creates both pass `find_one` and both insert. | 10 parallel POSTs with the same code give several 201s. | Rely on the unique index and map `DuplicateKeyError` to 409. |
| 10 | `create_employee` | `created_at = datetime.now()` is naive local time. The response returns a datetime string, but the contract needs epoch ms. | Response has `"created_at": "2026-...T..."`. | Use an aware UTC `now()` and serialise to epoch ms. |
| 11 | `list_employees` | `skip = page * page_size` skips the first page. | `page=1` returns items 21 to 40. Items 1 to 20 are never shown. | `skip = (page - 1) * page_size`. |
| 12 | `list_employees` | `total` counts the whole collection, ignoring the department filter. No sort by `emp_code`. No bounds on `page`/`page_size`. | `?department=Eng` returns total = all employees. `page=0` or `page_size=10000` is accepted. | `count_documents(q)`, `.sort("emp_code")`, `page >= 1`, `1 <= page_size <= 100`. |
| 13 | `PunchInIn` | `punched_at: Optional[int]` accepts floats, numeric strings and second-sized values. `status: str` accepts anything, including ABSENT. | `punched_at: 1783312500` (seconds) gives a 1970 date. `"status": "FOO"` returns 201. | `StrictInt` in the range 1e11 to 4102444800000. `status` is a `Literal` of the presence statuses. |
| 14 | `punch_in` | Unknown employee: `emp` is `None`, so `emp["shift_start"]` raises and returns 500. | POST with `EMP9999` returns 500. | Look up first and return 404. |
| 15 | `punch_in` | `datetime.fromtimestamp(ms/1000)` uses the server's local time zone. The date is the server-local date, not the IST date. No overnight rule (R1). Milliseconds are not truncated. | On a UTC server, a punch at 01:00 IST gets the previous day's date. Night-shift punch at 01:00 gets today's date instead of yesterday's. | `ms_to_dt` (UTC, whole seconds) and `attendance_date()` implementing R1. |
| 16 | `punch_in` | Check-then-insert duplicate check is not race-safe. | 10 parallel identical punch-ins give more than one 201. | Unique index on `(emp_code, date)`. `DuplicateKeyError` returns 409. |
| 17 | `punch_in` | Response leaks an `id` (the ObjectId) and returns datetimes instead of epoch ms. | Response has `"id": "66..."` and ISO strings for `punch_in`. | `serialize_record()` builds the contract shape with no `_id`/`id` and with ms instants. |
| 18 | `list_attendance` | Loads every matching document into Python, then sorts and slices. Too slow and memory-heavy at 100k. | 100k records: slow response and high memory use. `explain` shows COLLSCAN. | Filter, sort, skip and limit in MongoDB, backed by `date_desc_emp_code`, `uniq_emp_code_date` and `status_date_emp_code`. `total` comes from `count_documents`. |
| 19 | `list_attendance` | Sort has no `emp_code` tie-breaker, so order within a date is random. It returns `id` and raw datetimes, and does not fill missing `history` or `half_day`. | Two records on the same date come back in varying order. A legacy record has no `half_day` key. | Sort `(date desc, emp_code asc)`. `serialize_record` fills defaults. |
| 20 | `list_attendance` | No validation of `date_from`/`date_to` format, `date_from > date_to`, `status` value or page bounds. | `date_from=2026-07-09&date_to=2026-07-01` returns 200 with nothing. Expected 422. | `DateStr`/`Status` types, an explicit 422 for reversed dates, and page bounds. |

**Looked at and decided not a defect**

- `load_dotenv()`: the default `override=False` already lets real environment variables win over `.env`. I made it explicit anyway.
- `IST = timezone(timedelta(hours=5, minutes=30))` is correct.
- `compute_overtime` using the record's `date` as the base day is correct for day shifts. Only the overnight case needed the +1 day.
- Using `int()` to floor minutes in the helpers works for positive values. I still switched to `//` on whole seconds so negative values cannot round towards zero by surprise.
